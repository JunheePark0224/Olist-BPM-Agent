# comparison/ — 대조군

같은 Olist 배송 데이터를 분석한 다른 두 방식의 산출물이다. 옛날 파일 모음이
아니라 **파이프라인의 결과를 비교·검증하기 위한 대조군**으로 보관한다.

검증 결과와 재현 방법은 [`docs/verification.md`](../docs/verification.md)에 있다.

| 파일 | 무엇인가 | 어떻게 만들었나 |
|---|---|---|
| `manual_v3.pptx` | 수동 분석 덱 (13장) | [`notebooks/`](../notebooks/)의 Jupyter 분석을 손으로 슬라이드화 |
| `oneshot_llm.pptx` | 원샷 LLM 덱 (15장) | **CSV 9개를 단일 프롬프트로 던져 한 번에 생성.** 이 저장소의 코드와 무관하며, 재실행하면 다른 결과가 나온다 |
| `*.png` | 수동 분석 차트 | 노트북에서 내보낸 이미지. `manual_v3.pptx`에 사용됨 |

## 각 산출물에 대해 확인된 사실

**`manual_v3.pptx`** — 슬라이드 7의 `Product Category η²=12.8%`는 **틀린 값**이다.
노트북이 `order_items`를 두 번 조인해 108,581행이 151,581행으로 복제됐고,
설명력이 53% 부풀려졌다. 실제 값은 8.35%.

**`oneshot_llm.pptx`** — 주장 수치 24개 중 21개가 소수점까지 정확하다. 분석 깊이는
세 산출물 중 가장 뛰어나다(거리 반응곡선, ΔR², ICC/Design Effect). 다만 리뷰 관련
4개 값(지연 시 1–2점 56.7% 등)은 여섯 가지 집계 방식 어느 것으로도 재현되지 않으며,
그중 하나는 Executive Summary에 실려 최종 권고의 근거가 된다.

## 왜 남겨두는가

이 두 덱이 없으면 파이프라인의 값이 맞는지 알 방법이 없다. 조인 버그는 수동
분석과 대조했기 때문에 드러났고, 파이프라인의 η² 값은 원샷 LLM이 독립적으로
같은 값을 내놓아 교차검증됐다.

`oneshot_llm.pptx`의 오류를 찾을 수 있었던 것은 파이프라인이
`agent/outputs/processed_dataset.parquet`를 남겨두었기 때문이다. 덱 자체에는
코드도 중간 산출물도 없어 읽어서는 검증할 수 없다.
